# 유키 마코토 대역의 위쪽 공격 방향 복구

2026-10-25. 로컬 수정이며 커밋·푸시·운영 배포하지 않았다.

## 원인

기본 외형과 스킨 모두 Back 모델에 대역 1스킬 일반 공격·대기, 2스킬 Loop, 3스킬 첫 대역 일반 공격 A/B·대기 모션이 존재한다. 반면 SwitchIn/Out은 Front 모델에만 있다. `_wantsBack()`이 대역의 전체 수명 동안 전환 클립까지 Back에 존재해야 한다고 판단해 UP 배치에서도 Front를 계속 사용했다.

## 수정

- Front 전용 진입/전환 모션은 해당 전환 구간에만 Front로 표시한다.
- 안정 상태에서는 해당 대역의 대기·공격 모션을 기준으로 Back 사용 여부를 결정한다.
- 진행 중인 공격은 기존 모션 재개 경로로 이어가며 A/B 순서를 재시작하지 않는다.
- 3스킬 두 번째 대역의 `Doll_Skill_3_P2_Loop`은 기본/스킨 Back 리소스에 없어 Front fallback을 유지한다. 존재하지 않는 뒤쪽 모션을 새로 만들지는 않았다.
- 시뮬레이션·공격 판정·SP·전환 보호 시간은 변경하지 않았다.

## 검증

- 실제 기본/스킨 메타데이터를 사용하는 회귀에서 수정 전 UP 대역이 Front에 고정되는 실패 재현. [수정 전](regression-before.log).
- 전환·공격 재개·기절·간소 FX·스킬 앞뒤 선택·마코토 전투·공전 효과 회귀 **62개 모두 통과**. [결과](tests-after.log).
- Chromium 실제 전투: 기본/스킨 × S1/S2/S3 첫 대역 **6조건**에서 수정 전 Front, 수정 후 Back 확인. 공격/Loop 클립 종류 유지, 3스킬은 같은 공격 재생 시각. S1/S2의 방향 전환 후 샘플 재생 시각 차이는 0.04초 미만. [수정 전 측정](browser-before.json), [수정 후 측정](browser-after.json). 두 실행 모두 JavaScript 오류 0건.
- 실제 화면: [3스킬 스킨 수정 전](s3-skin-before.png) / [수정 후](s3-skin-after.png).
- 변경 파일 lint 오류 0개(기존 units.js 경고 5개), `git diff --check` 통과.

기존 테스트 링크의 서버를 재시작해 반영했다. 브라우저 새로고침이 필요하다.
