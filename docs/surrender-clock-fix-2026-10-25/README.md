# 전투 포기 시 브라우저보다 앞선 처치 인정 방지

2026-10-25. 일반 라운드·증강 없음·테스트 서버에서 HP 10이 여러 라운드 유지됐다가 다시 차감된다는 제보를 조사했다. HP 10 자체의 하한은 재현되지 않았고, 클라이언트 전투가 서버 벽시계보다 뒤처졌을 때 같은 결과를 만드는 경로를 재현했다. 당시 방의 실제 프레임 기록은 없어 제보 당시 지연 크기까지 확정한 것은 아니다.

## 원인 및 수정

`Match.endBattle()`은 포기 시 서버가 해당 전투를 다시 실행하는데, 종료 시점을 `_fieldElapsed()`의 벽시계 기준으로 정했다. 로딩·백그라운드 제한·전투 지연으로 브라우저가 뒤처졌다면 아직 하지 않은 공격과 처치를 재계산 중 실행할 수 있었다. 모든 적을 미래 시점에 처치한 결과가 만들어지면 누락 적 수가 0이 되어 포기해도 일반 정산 HP가 줄지 않았다.

- 포기 요청에 현재 표시 전투의 최신 스냅샷 시간 `gt`를 선택적으로 전송한다. 실제 수신 중인 스냅샷도 시간 버퍼에 갱신한다.
- 서버는 전투 authority가 보낸 시간만 사용하며, 기존 `b.progress.gt`보다 과거로 돌아가지 않고 서버 경과 시간을 넘지 않도록 제한한다.
- 요청 시각이 없는 구형 클라이언트는 마지막 진행 보고 시점을 사용한다.
- 이미 서버가 실행하는 전투와 보스전의 종료 규칙은 유지한다. 포기 이전에 실제 완료된 처치와 그 시점의 전투 결과를 보존하고, 이후 처치를 미리 인정하지 않는다.

## 검증

- 지연 재현: 서버 경과 30초, 마지막 클라이언트 진행 1초, 3초에 적이 처치되는 조건. 수정 전에는 미래 처치가 인정되어 HP가 유지되고 회귀 테스트가 실패했다. 수정 후에는 1초까지만 재계산하고 남은 10명을 정산해 HP 10→0으로 감소한다.
- 최신 스냅샷/과거 스냅샷 모두에서 포기 전에 완료한 1명 처치는 유지하며 나머지 9명만 차감(HP 10→1).
- HP 10에서 정상 진행 중 포기하면 client/server 방식 모두 HP 0·탈락, 공개/개인 상태 값도 0.
- 포기·돌파·공유 HP·연합방어·로컬 전투 runner·증강 회귀 **102개 전부 통과**. [수정 전 재현](regression-before.log), [수정 후 검증](tests-after.log).
- 관련 파일 lint 오류 0개(기존 경고 36개), `git diff --check` 통과.

테스트 서버에 반영했으며 커밋·푸시·운영 배포는 하지 않았다.
