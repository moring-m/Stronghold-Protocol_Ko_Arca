# UI 배율·투사체·SFX·렌더 경계 점검

## UI 배율

기존 구현은 모바일 viewport 메타 태그만 변경해 데스크톱 브라우저에서는 효과가 없었습니다. 데스크톱은 CSS 레이아웃 zoom을 적용하고, 모바일은 기존 네이티브 viewport 배율을 유지합니다. 터치스크린 Windows PC도 데스크톱 경로를 사용합니다. 전체화면 변경 이벤트에서도 설정을 다시 적용합니다.

Viewport 크기를 사용하는 패널의 경계는 배율로 보정하고, 캔버스의 입력 좌표·타일 안내·오퍼레이터 조작판·방향 선택·도움말 위치를 CSS zoom과 맞춥니다. 100%의 기본 스타일은 유지합니다.

실제 Chromium 화면과 측정값(`browser-check.json`):

- [100%](scale-desktop-1.png), [80%](scale-desktop-0.8.png), [125%](scale-desktop-1.25.png)
- 1280×720에서 제목 너비 449.2 → 359.3 → 561.5px. 화면은 각 배율에서 1280×720을 채웁니다.
- 1920×1080 및 fullscreenchange 이벤트에서도 같은 배율을 유지합니다.
- 이 환경의 headless Chromium은 아무 스타일이 없는 페이지에서도 네이티브 requestFullscreen을 완료하지 못했습니다. 따라서 OS 전체화면 전환 자체를 검증했다고 주장하지 않습니다. 전체화면 이벤트·크기 변경 경로와 배율 유지를 검증했습니다.

## 산탈라 2스킬

`projectile_chr_sntlla_s2`에는 main 효과가 없고 onReached의 `sntlla_skill_02_start_01`이 낙하 얼음덩이입니다. 시뮬레이션은 일반 공격 투사체 대신 iceSpike 이벤트로 낙하를 처리하지만 해당 공식 연결이 없었습니다. 이제 실제 선택 타일에 공식 낙하 효과를 연결하고 사전 로딩합니다.

착지 음원도 일반 공격 이벤트로는 재생되지 않았습니다. 시뮬레이션 착지 시점에 별도 phase를 보내 한 번 재생하도록 연결했습니다. 피해·공격 간격은 변경하지 않았습니다.

[실제 공식 렌더 화면](santalla/shots/char_341_sntlla-official.png). `santalla/captures.json`에 로딩된 prefab과 오류 여부를 기록했습니다. 같은 main 없는 제어 투사체를 사용하는 이네스·혼·로즈몬티스·피아메타·첸 더 홀룽데이·위샤델은 기존 _arrive/onReached 또는 별도 스킬 바인딩 경로를 확인했습니다. 이는 모든 오퍼레이터를 실전 전수 촬영했다는 뜻은 아닙니다.

## 다른 SFX 누락

[보완 목록](SFX-LIST.md)에 45명의 직접 은행 매핑 누락과 산탈라의 이벤트 누락을 별도로 기록했습니다. 기존 매핑과 명시적 무음은 덮어쓰지 않았으며, 반복 파일을 일회성 시작 음원으로 잘못 추가하지 않도록 제외했습니다. 필요한 고유 음원 22개와 산탈라 착지 음원의 HTTP 200을 확인했습니다. 데이터 재생성 경로도 보완했습니다.

## 스킨 SFX

현재 공식 은행에서 별도 전투 SFX가 확인되는 스킨은 다음 4종입니다.

| 오퍼레이터 | 스킨 식별자 |
| --- | --- |
| 스카디 더 커럽팅 하트 | iteration#2 |
| 이그제큐터 디 엑스 포에데레 | sanrio#2 |
| 에이야퍄들라 | sanrio#2 |
| 골든글로우 | sanrio#1 |

은행·파일 목록은 `skin-sfx-banks.json`에 기록했습니다. 현재 자료에서 확인한 목록이며 다른 스킨에 차이가 없다는 뜻은 아닙니다. 기존 FX 추출본은 AudioClip 음원 추출본이 아니므로, 스킨별 음원 교체가 구현되어 있다고 주장하지 않습니다. [Windows 추가 추출 안내](SKIN-AUDIO-EXTRACTION.md)와 ZIP 추가 도구를 준비했습니다. 설치된 클라이언트가 없는 이 환경에서 실제 Windows 추출 실행은 검증하지 못했습니다.

## 이펙트 일부가 잘리는 공통 경로

기존 공식 GL 패스는 Pixi가 이전에 사용한 SCISSOR_TEST·STENCIL_TEST를 그대로 유지했습니다. 배치·그리기 순서에 따라 다른 영역이 잘릴 수 있는 공통 경로입니다. 이제 공식 효과와 지형 depth clear 동안 두 상태를 분리하고, 렌더 이후 이전 상태를 복원합니다. 원본 ZTest·렌더 큐·지형 깊이·유닛 정렬은 유지합니다.

브라우저 WebGL 검사에서 이전 사각형 잘라내기가 설정된 상태에서도 전체 16×16(256픽셀)이 렌더링되고, 이후 사각형·스텐실 상태가 복원되며 GL 오류가 없는 것을 확인했습니다. 첨부하신 정확한 장면을 재현한 것은 아니므로 이것만으로 모든 잘림 원인이 해결됐다고 단정하지 않습니다.

## 검증 범위

관련 UI·음원·정렬·기록·스킬 바인딩 검사 225개를 통과했습니다. 산탈라 콘텐츠 검사 4개, 전용 착지 이벤트 검사 3개와 추출기의 선택적 내보내기·원본 보존 검사도 통과했습니다. 화면 크기·배율 및 GL 잘라내기 상태는 브라우저에서 별도로 확인했습니다.

추가 HUD 회귀 검사 중 기존 CSS 문자열 검사 1건은 실패합니다. 테스트는 맹약 띠 top을 1.36rem으로 기대하지만, 수정 전 HEAD와 현재 CSS 모두 이미 1.13rem입니다. 이번 배율 수정으로 생긴 차이가 아니어서 이 작업에서 해당 배치를 바꾸지는 않았습니다.
