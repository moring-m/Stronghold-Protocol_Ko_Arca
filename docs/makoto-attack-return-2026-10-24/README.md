# 유키 마코토 기본 공속 공격 동기화

조건: 위쪽 배치, 스킨 착용, 대역에서 본체 복귀 후 공격. 기본 외형도 같은 경로를 검사했다.

## 확인한 문제와 수정

- 전환은 Front 모델로 재생하고 위쪽 본체는 Back 모델로 돌아간다. 이 비동기 교체 중 이미 시작한 공격 상태가 새 actor에 전달되지 않아, 타격 시점에 공격을 처음부터 다시 재생했다. 시작 시각·A/B 변형·선딜·주기·타격 여부를 기록하고 교체된 모델에 경과 시간을 적용한다.
- 보호 시간이 끝나 서버가 첫 공격을 허용했는데, 렌더러에는 전환 마지막 프레임이 남아 있는 경우 공격 시작을 거절했다. 공식 잔상은 시작되고 몸체는 뒤늦게 타격 이벤트에서 시작할 수 있었다. 마코토의 공격 가능한 형태에서 권위 있는 공격 시작 이벤트를 받으면 남은 전환을 완료하고 같은 공격을 시작한다.
- 취소·실제 형태 변경 시 기록을 버리고, 이미 끝난 공격은 복원하지 않는다. 타격 뒤 모델 로드가 끝나더라도 선딜을 다시 재생하지 않는다.

공속 상한은 이번 기본 공속 제보의 원인이 아니다. 실전 데이터의 S3 첫 대역은 공격 선딜 약 0.49042초, 애니메이션 재생 속도 약 1.63125로 이펙트 상한 2보다 낮다. 검토 중 추가했던 상한 우회는 제거했으며 원본 이펙트의 속도 제한을 유지한다. 서버 공격·피해·SP·대역 지속시간 규칙은 이번 수정으로 변경하지 않는다.

## 검증

- Front→Back 교체 회귀: 수정 전 `base !== attack` 실패, 수정 후 기본/스킨 모두 공격 클립과 경과 시간 유지.
- 기본 공속 전환 경계 회귀: 수정 전 `change !== attack` 실패, 수정 후 기본/스킨 모두 즉시 공격 A 시작. 타격이 트랙을 재시작하지 않고 다음 공격은 B로 진행.
- 지연 로드가 타격 이후 완료되는 경우, 취소된 공격 및 만료된 공격 재생 방지 검사 통과.
- 관련 전투·이펙트·성능·적 공격 회복 테스트 92개 통과. import 검사 통과, 대상 ESLint 오류 0개(기존 경고 있음).

단위 검사는 실제 클립 메타데이터와 테스트용 Pixi를 사용한다. 별도 Chromium 전투 재생은 실제 스킨·Spine·공식 FX를 사용한다. 모든 오퍼레이터와 모든 네트워크 지연 조건의 검증을 의미하지 않는다.

실제 Chromium 재생: 기본/스킨 모두 위쪽 배치로 31초 전투를 재생했다. 첫 대역 공격과 28.067초 본체 복귀 공격에서 attack 상태가 유지되고 다음 공격은 반대 A/B 클립으로 진행했다. 브라우저 오류는 없었다. 기록은 [battle-feed-validation.json](battle-feed-validation.json), 실제 스킨 복귀 후 화면은 [up-skin-body-attack.png](up-skin-body-attack.png)에 저장했다. 비동기 모델 교체 및 렌더 주기로 1~2프레임의 표본 오차는 있어 모든 프레임이 수학적으로 동일한 위상이라고 주장하지 않는다.
