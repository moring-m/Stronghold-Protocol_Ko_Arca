# Forge 플러그인 병합·호환성 검토 (2026-10-18)

검토 원본: https://github.com/XiaMo233M/Stronghold-Protocol-Forge-Mods/tree/0dc1a4fc9db9ead85bf41258046e92065bbf6e5f

현재 병합본 도구로 배포 목록 30종, 구버전 ZIP 1개, 풀린 소스·예제·퇴역 demo 14개를 포함해 총 45개를 dry-run 검증했다. 등록된 ZIP 30개의 SHA-256은 index.json과 모두 일치한다. 이 검토는 설치·실행·운영 적용을 하지 않았다. 패키지 스크립트는 파싱만 했으며 실행하지 않았다.

공식 캐릭터·스킬·범위·모듈·활동 표 6개를 별도 임시 디렉터리에 준비해 재검증했다. 표가 없어 누락된 경우와 실제 API 비호환을 구분했다. 현재 커스텀 production/data를 복사한 격리된 검증 데이터를 사용했다.

## 판정 기준과 한계

- 도구 통과는 JSON/잠금/개별 content set 또는 visual set 검증 성공이다. 실제 전투 효과·UI 렌더링·한국어·여러 패키지 동시 선택이 모두 정상이라는 의미가 아니다.
- 45개 중 도구 성공 44개, 실패 1개(Ave Mujica). 배포 목록 30종 중 제품 생성+비부분 판정 15종, 부분 5종, 제품 없음 9종, 실패 1종. 단, 유키 마코토의 일반 kit 대체는 도구가 partial로 표시하지 않아 이 보고서는 전투 미호환으로 별도 분류한다.
- 화면 아래 표 이름은 설명용 한국어다. 원본 공지/콘텐츠는 중국어가 남아 있어 실제 적용에는 한국어 번역이 필요하다.
- 기존 오퍼레이터와 같은 charId라도 플러그인의 기물 id는 별도 namespace다. 기존 선발·중복 금지·오퍼레이터 밴을 원본 charId까지 매핑할지 확인해야 하며, 동일 캐릭터를 새 ID로 더하는 것을 자동 호환으로 보지 않는다.
- 현재 가져오기 도구의 pack 단계는 전달된 dataDir를 일부 packPlugin 호출에 넘기지 않는다. Ave Mujica의 origin 검사 실패는 이 경로와 기본 data/에 공식 출처 레코드가 없는 조건을 함께 조사해야 한다. source 검사 자체를 삭제해서 우회하면 안 된다.

## 병합하는 방법

1. 원본 ZIP의 SHA-256과 정확한 버전을 고정한다. `mods/`와 `packs/`에 같은 ID가 있으면 둘을 비교하고 하나만 고른다.
2. 현재 production 데이터로 `node tools/plugin.mjs import-forge <패키지 경로> --dry-run --json`을 실행해 skipped/dropped/manualReasons를 검토한다. 공식 표가 필요한 경우 한 번 다운로드하고 이후 오프라인 검증한다. 현재 CLI 기본 data/와 production/data가 다른 로컬 환경에서는 검사 경로를 일치시켜야 한다.
3. 기능 누락 없는 항목만 `import-forge <경로> --out plugins/<id>`로 생성한다. 생성된 기본·외형·스크립트 제품을 모두 식별하고 `check --strict`, `pack`을 거친다. 원본 install.mjs나 서버 덮어쓰기 스크립트는 실행하지 않는다.
4. 맹약 엔진·특질·스킬이 빠지는 오퍼레이터 패키지는 DSL/SDK로 해당 동작을 먼저 구현한다. generic kit 대체를 완전 병합으로 취급하지 않는다.
5. 설치한 플러그인은 방의 콘텐츠 선택에서 명시적으로 선택한다. 스크립트 제품은 별도 샌드박스 실행 설정과 동의가 필요하다. 기존 사용자 설정을 보존하고 기본 활성화하지 않는다.
6. 한국어, 밴/선발, 재고, 중첩, 통계(연습실 포함), 4/8인, 관전, 보스 스탯/시간, 공식/간소 이펙트를 검증한다. 조합할 플러그인끼리도 검증한다.
7. 검증 후 코드·필요 데이터/합법적으로 배포 가능한 파일만 버전 관리하고 새 버전으로 배포한다. Docker는 plugins/를 런타임 plugin-resources로 복사하는 구조이므로 폴더를 추가하기만 하고 방에 선택하지 않으면 활성화되지 않는다.

## 우선순위 제안
