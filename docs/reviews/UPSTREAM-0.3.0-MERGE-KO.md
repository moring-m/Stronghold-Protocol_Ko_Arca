## 5. 리소스 용량과 시각적 변화

**시각적 변화가 전혀 없는 병합은 아닙니다.** 일반 전장의 물·조명·반사와 공식 공격/스킬 이펙트, 통계 화면은 바뀝니다. 8인 전장의 지형 연결·4전장 배치·카메라를 새 원본의 4인 지형으로 바꾸지는 않습니다.

공식 v0.3.0 전체 ZIP의 SHA-256 `5bf3cf3797902e8441aca211706630254c7ebb9636fa0baf301e6c179efcd5b7`를 검증한 뒤 시각 리소스만 추출합니다. 업데이트 전용 ZIP에는 일부 기존 `scene.bin`이 없어 전체 ZIP을 기준으로 했습니다. 전체 ZIP의 게임 실행 코드·오퍼레이터 수치·음성은 덮어쓰지 않습니다.

### 후속 점검: 화면 복귀·공통 설정 테마·캐시 경로

- 오퍼레이터 설정 호스트가 닫히며 제거될 때 `sp-loadout-open` 클래스가 남아 원래 화면을 숨기는 문제를 수정했다. 공통 `useDocClass`의 unmount 정리를 사용한다. 실제 돌아가기 버튼과 Esc, 반복 열기/닫기를 브라우저에서 확인했다.
- 설정/커스텀/선호·선발 프리셋의 공통 스타일을 `css/settings.css`로 분리해 처음부터 로드한다. 전투 전용 CSS는 계속 지연 로드한다.
- 전투 통계는 기존 전투 결과 기록과 별개인 실시간 DPS/HPS 패널이다. 사용자 요청의 조건에 따라 기본값은 변경하지 않았다.
- v0.3.0 가져오기 캐시가 해시 URL을 처리할 때 캐시 miss를 곧바로 서버 요청으로 보내던 경로를 수정했다. 가져오기 캐시 hit가 없으면 기존 canonical 캐시/미러 다운로드로 이어진다. 공유 resource worker 등록에도 `type: module`을 명시했다. 전체 리소스 다운로드는 유지한다.
- 브라우저 화면 복귀/지연 로딩 + 리소스 캐시 + 가져오기 + CSP 대상 검증 35개 통과. worker 모듈 등록 회귀 사례를 추가한 가져오기 검증 17개도 통과했다. `git diff --check` 통과.
- 별도 글자 크기 정적 검사에는 실험실의 기존 rem 규칙과 현재 HUD의 `--t` 스타일을 과거 rem 값으로 가정하는 검증 등 2개 실패가 남는다. 이번 화면 복귀/캐시 검증의 실패는 아니다. 공통 CSS 이동에 따른 경로와 기존 편집기 글자 크기 제외 목록은 갱신했다.

운영 사이트는 아직 0.2.6e이므로 새 로컬의 0.3.0 리소스를 운영 트래픽 증가 원인으로 볼 수 없다. 운영 사이트가 공개하는 리소스 목록의 개별 파일 크기 합계는 GitHub raw 772.3MiB, jsDelivr 228.7MiB, 자체 제공 116.7MiB다(목록의 별도 estimatedBytes 값은 약 1,103MiB). 자체 제공분에는 추출 맵/커스텀 모델·음원 등이 포함되며, 동의 후 전체 백그라운드 다운로드 대상이다. 따라서 미러 미사용 문제는 아니지만 자체 제공분만으로 보고된 서버 송신 300MB 전부를 설명할 수 없다. 운영 워커의 접속 전후 `healthz?traffic=1` 결과로 HTTP/웹소켓 송신을 추가 구분해야 한다. 운영 변경·배포는 하지 않았다.
