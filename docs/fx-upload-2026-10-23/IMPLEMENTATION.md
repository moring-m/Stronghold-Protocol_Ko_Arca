# 누락 기본 FX 추가 및 스킨 추출 준비

## 기본 FX 연결

기존 인덱스에 유닛 키가 없던 9명(비헌터·보타니·레토·우쿠시크·이스티나·토가와 사키코·체르니·디아만테·베이스라인)을 추가했다. 기존 유닛·스킬·투사체·부착 좌표·프리팹 키는 우선 보존하며, 동일 경로에 다른 바이트가 있으면 설치를 중단한다. 일반 이펙트의 크기·좌표·타이밍 코드는 변경하지 않았다.

참조를 따라 필요한 추가분만 추려 프리팹 107개·텍스처 67개·메시 23개, 페이로드 파일 264개(4,015,753바이트)를 포함했다. 기본 묶음에 이미 있는 공용 파일은 재사용한다. 별도로 갱신하는 인덱스와 텍스처 목록은 기존 데이터에 추가 키만 합친다.

- `tools/fx-supplement.mjs prepare`: 기존/새 추출 결과에서 누락 유닛과 그 의존 파일만 추림.
- `tools/fx-supplement.mjs install`: 기존 키 보존·해시 검증 후 파일/다운로드 목록에 추가.
- Docker는 원본 공식 FX 설치 후 추가분 설치를 실행하므로, 원본 ZIP이 추가분을 다시 덮어쓰는 문제를 피한다.
- 추가분은 `content/custom/fx`에 준비했다. 별도 GitHub 리소스 저장소는 만들거나 게시하지 않았다. 현재 빌드 방식으로는 배포 이미지에 포함돼 운영 서버에서 제공된다.

실제 Chromium의 FX 뷰어에서 9명 각각의 대표 공격 이펙트를 불러와 렌더링했으며 파일 로딩 실패와 JS 오류는 없었다. 이는 공식 FX 렌더러의 표시 검사이며 실제 전투의 모든 스킬·타이밍 비교를 뜻하지 않는다. [검증 로그](browser-check.json), [실제 렌더링 이미지](screenshots/).

JS 관련 테스트 45개 통과. 추출 도구의 코스튬 매칭·기본 파일 제외 테스트 3개 통과. 기존 한국어 음성 보완 테스트도 통과.

## 스킨 추가분 추출 도구

기존 Windows 키트 폴더에 업데이트 ZIP을 풀고 `SKINS.cmd`를 실행한다. 기존 `.venv`와 `prepare_client.py`를 사용하며, 전체 기본 추출용 `START.cmd`는 실행하지 않는다.

새 도구는 현재 게임 오퍼레이터에 해당하는 공식 코스튬 메타데이터 283개를 기준으로 코스튬 프리팹의 컴포넌트·교체 설정·부착 좌표·참조 이펙트를 수집한다. 기본 FX에 이미 있는 프리팹·텍스처·메시는 출력에서 제외한다. 기본 결과와 원본 클라이언트는 수정하지 않고 별도 `skin-output-날짜`에 출력한다. 7-Zip이 있으면 자동으로 20MB 분할 압축한다.

실제 한국 PC 클라이언트에서 실행한 검증은 아직이다. 따라서 매칭 실패 항목과 오류도 보고서에 포함하고, 0개로 나온 경우 기본 FX 전체를 다시 추출하게 하지 않는다. 새 도구의 출력은 바로 적용 가능한 스킨 런타임 팩이 아니라, 실제 교체 필드를 확인해 연결하기 위한 자료다.

다운로드 ZIP에는 게임 리소스 원본이 아니라 Python/PowerShell 스크립트, 스킨 메타데이터와 기본 FX 키 목록만 들어 있다.

## Windows 추출 로그 후속 수정

사용자 실행에서 260개 코스튬이 매칭됐으나, 기존 스킨 전용 추출은 FX 프리팹만 추출해 투사체/스킬 연결 인덱스가 0개였다. 시각 프리팹 외에 이동·도달·명중·소멸·연쇄 투사체와 새 스킬 연결도 필요하므로 `complete_skin_fx.py`와 `COMPLETE_SKINS.cmd`를 추가했다. 기존 `skin-effects.json`과 클라이언트 하드링크 뷰를 재사용하고 별도 followup 폴더에 쓰며, 기존 기본 FX와 기존 스킨 결과에 없는 시각 파일만 추가 추출한다. 이후 SKINS 실행도 투사체 연결을 함께 수집하도록 했다.

기본 FX 파서의 투사체 부분을 재사용 가능한 `projectile_entries()`로 추출했다. 원래 기본 FX 추출도 같은 파서를 사용한다. 비행/수명·이동·연결선·명중·소멸·자식 투사체, 기존 키 보존을 모의 Unity 환경으로 검사했다. 보완 단계가 기존 추출 결과를 변경하지 않고 이미 있는 시각 파일을 다시 추출하지 않는 테스트도 통과했다.

공유 텍스처 저장 중 WinError 5에 대비해 원자적 저장에 고유 임시파일·동일 바이트 확인·제한된 재시도를 적용했다. 거부된 다른 바이트를 성공으로 간주하지 않으며 실패 시 기존 파일을 유지한다. 경고가 난 Default-Particle-4350037b는 기본 묶음에 이미 있는 키다. 기존 결과의 경고가 해당 프리팹 재질에 미친 영향은 결과 업로드 후 확인해야 한다.
